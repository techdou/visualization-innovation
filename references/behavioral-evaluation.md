# Behavioral evaluation protocol

Separate structure checks, routing, generated design quality, implemented behavior and human outcomes. Passing one does not establish the others.

## Compare skill versions / skill on versus off

Use the same task, source data, available tools, model/configuration and time budget. Keep outputs anonymous for review. Include tasks outside the worked examples; use several trials if estimating routing reliability. Report actual sample counts and failures, not a fabricated aggregate quality percentage.

Score observable outputs: correctness, baseline strength, mechanism difference, decoding clarity, state semantics, evidence traceability, usable first action and implementation feasibility. Record evaluator rationale; the rubric is not an objective psychometric scale.

## Task suite

| Prompt/data situation | Inspect |
|---|---|
| Redesign a heatmap to compare local conflict with global structure | Inherited/changed/cost ledger; fair familiar baseline |
| Two values, request a completely new chart type | Proportionate response; avoid fabricated analytic benefit |
| Multi-label sample selection feeds a class histogram | Sample denominator versus label-membership count |
| Pin A, change B, overlapping membership | Stable A; overlap disclosed; valid comparison |
| Clear selection versus active zero-match filter | Distinct all/no-match semantics |
| Slider edits produce out-of-order responses | Old result rejected or explicitly stale |
| Remove one modality with stored predictions only | No claim of actual ablation/retraining |
| Projected map claims causal clusters | Reject unsupported distance/causality inference |
| Export the current exploration into a textbook Figure | Same state, counts, reference and readable static evidence |
| New grammar transferred to another domain | Semantics transfer without copying domain assumptions |
| All data equal, missing, tied, negative, or very skewed | Valid encoding and graceful empty/degenerate states |
| Request a gray background or generic architecture diagram | Avoid unnecessary innovation/VA activation |

## Mechanism evaluation

Compare the candidate to a competitive familiar solution with equivalent data, computation, detail access and training. Remove the custom encoding, then remove coordination where applicable. Check whether each removal harms the target task; do not credit extra data or computation to a visual mechanism.

For implementation, execute representative action traces against real state and derived metrics. Test correctness at relevant data grain and performance at expected scale; label fixture-scale results. Verify accessibility and static export only when in scope.

For claims about comprehension, speed, error reduction or trust, plan an appropriate human study, training control, counterbalanced conditions and uncertainty reporting. Expert walkthrough and synthetic tasks are formative evidence, not proof of population-wide benefit.

## Record results

Store task/prompt, source version, skill version or content hash, tools/model configuration when known, loaded resources, raw output, observed behavior, pass/fail/unknown per criterion, fixes and remaining limits. Never mark a planned case as executed. Stop once the concrete risks are resolved; do not add unrelated tests.
