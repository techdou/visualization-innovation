# Divergent–Convergent Ideation Workflow

## Frame
Record task, target relation, baseline, limitation, user expertise, data scale, medium, and evaluation objective.

## Extract domain primitives
List entities, transitions, constraints, causes/effects, layers/scales, confidence, routes, hierarchies, episodes, missing states, and expert actions. Domain practice can expose design primitives.

## Choose design-space axes
Select a few orthogonal axes, e.g. layout (axis/anchor/force), comparison (overlay/difference/small multiple), interaction (brush/manipulate/steer), story (free/guided/branch), evidence (aggregate/trace-to-sample).

## Generate families
A useful trio:
- **Familiar+** — improve a conventional encoding.
- **Recombined** — combine proven mechanisms for a new workflow.
- **Speculative** — a bolder metaphor/layout/interaction with explicit risk.

## Mutation operators
absolute→difference; item→group→field; axis→anchor; global→lens; static→manipulable; value→uncertainty; observed→missing/gap; single view→coordinated state; final state→history; chart→embedded micro-view; read-only→authorable; linear story→branchable story.

## Converge
Reject candidates that do not improve a target judgment, demand excessive decoding, fail to scale, duplicate prior art without a new purpose, cannot be evaluated, or only add decoration.

## Prototype hypothesis
> If the user can perceive/manipulate ___ through ___, they should be better able to ___ than with ___ because ___.
